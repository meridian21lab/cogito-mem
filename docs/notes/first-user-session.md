# First-user session (19 Oct 2026)

The author installs and learns cogito-mem as a newcomer would. Every question goes here, with the answer and
what the docs must do about it. The user guide and the GitHub Pages site are built from this list.

## The essence (what the 19 questions boil down to)

A newcomer asks six things, in this order, and the docs answer them in this order:

1. **What is it?** (Q2, Q3) *"Every message is remembered; when something falls out of the context window, Claude
   gets it back."* One sentence and one picture: collect, keep, find.
2. **Is it worth it, compared with the others?** (Q19) Proof, not adjectives: the LoCoMo numbers next to Mem0 and
   Zep, and an honest "pick something else if".
3. **How do I install it?** (Q1, Q6, Q7, Q8, Q9) One command per copy block, each followed by what you should see;
   say which choice to make in each dialog; never let a helper's install look like the real one.
4. **Did it work?** (Q10, Q11, Q12, Q13) `/mcp` shows `plugin:cogito-mem:cogi ✔ 2 tools`; the status shows the
   model `ready` and the message count; the "acorn" test proves recall. The status is enough.
5. **Is it safe? What did I just install?** (Q14, Q15, Q17, Q18) A page listing every file, every download and
   every network connection, linked from the plugin's *Open homepage*; where Cogi works and where it doesn't.
6. **How does it work underneath, and how do I build on it?** (Q4, Q5, Q16) The basket (`max_tokens`), the hollow
   (the memory's name), and the API and MCP tools with real requests and replies.

Values the site keeps: simple words a child could follow; few words; one idea per section; Cogi the squirrel and
its nuts as the one running picture (messages are nuts, the memory is the hollow, the budget is the basket).

| 1 | "The best recommended usage is via Claude hooks?" | Half of it. | 2 | (How the user pictures it) "Each message and answer will be remembered. | 3 | "Could you explain how the service works?" | Cogi collects every message after each answer, keeps it word for word with its date, and finds it again by words and by meaning. ## Findings (friction seen on the way)

| # | What happened | Fix |
|---|---|---|
| F1 | Opening this repository in Claude Code shows a failing MCP server `cogito-mem` (`Connection closed`). The plugin's `.mcp.json` sits at the repo root, so Claude Code also reads it as the *project's* MCP config, where `${CLAUDE_PLUGIN_ROOT}` is empty and the command points at `/scripts/cogito-mem-plugin`. | Move the server into `.claude-plugin/plugin.json` (`mcpServers`), so only the plugin uses it. **Done** in the recall-hooks PR (meridian21lab/cogito-mem#4). |
| F2 | Claude Code saves its compaction summary as a `user` message (`isCompactSummary: true`); capture would store it as if the user had typed it. | Skip `isCompactSummary` records in `capture/claude_code.py` (later; not fixed during the session). **Done** on 20 Oct, together with background-task notifications (`<task-notification>`), which were stored the same way. |
| F3 | The user read the `uv` installer's "everything's installed!" as cogito-mem being installed. | Label step 0 "install the helper `uv`"; or have the plugin's first start install `uv` itself. |
| F4 | The plugin gives no `cogito-mem` command in the terminal, yet the guide told the user to run `cogito-mem capture claude-code --all`. | Docs: for terminal use, `uv tool install cogito-mem` (from PyPI since 0.2.1). Product: a `/cogito-mem` slash command, or backfill on first start. |
| F5 | `uv` lands in `~/.local/bin`; a Claude Code started from an older terminal may not find it on its `PATH`, and then the plugin's server and hooks fail. | Docs: open a new terminal (or `source ~/.zshrc`) before starting Claude Code. Product: the plugin's shim could also look in `~/.local/bin` and `~/.cargo/bin`. |
| F6 | Two slash commands pasted together run as one: the second became part of the first's argument (`'meridian21lab/cogito-mem /plugin install …' is not a valid GitHub owner/repo shorthand`). | Docs: never put two slash commands in one copy block. Product: an installer one-liner from the terminal (`claude plugin marketplace add … && claude plugin install …`) avoids typing slash commands at all. |
| F7 | There is no way to browse what is stored without `sqlite3`. | **Not needed** (user, later in the session): "I don't need to list the messages, the status is enough." Keep the `sqlite3` lines out of the main docs; the status is the view. |
| F8 | The status JSON says `namespaces.default` with no hint of what a namespace is or who chose it. | Product: status could say `"default": {"used_by": ["claude-code"], …}` or similar; docs: a glossary line. |
| F9 | Cloud agents are a natural question ("will Cogi work with cloud agents?") and the answer is no. | Product: a remote mode with sign-in (token over HTTPS), so cloud sessions and claude.ai can reach one memory; until then, say it plainly in the docs. |
| F10 | Claude Code in the desktop app was never tested with the plugin. | Test it before the docs claim it. |
